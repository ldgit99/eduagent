# 학생이 자주 막히는 지점

## 설치·환경

**"명령어를 찾을 수 없습니다"**
`uv tool install edu-agent-harness` 후 터미널을 새로 열게 하세요.
그래도 안 되면 Codespaces로 넘기는 것이 빠릅니다.

**한글이 깨져 보입니다 (Windows)**
하네스가 출력 인코딩을 UTF-8로 강제하지만, 터미널 자체가 오래된 경우가 있습니다.
Windows Terminal(기본 앱)을 쓰게 하세요. PowerShell ISE나 옛 명령 프롬프트는 피합니다.

**화살표 키가 안 먹습니다**
하네스는 화살표 선택을 쓰지 않습니다. 전부 번호 입력입니다 (`1`, `2`, `1,3,5`).

## API 키

**"API 키가 없습니다"**
1. `.env.example` 을 `.env` 로 복사했는지
2. `.env` 가 **프로젝트 폴더**(edu-agent.yaml 옆)에 있는지
3. `EDU_AGENT_API_KEY=` 뒤에 값이 붙어 있는지 (따옴표 불필요)

`edu-agent doctor` 가 어느 단계에서 막혔는지 알려줍니다.

**키가 오기 전에 뭘 할 수 있나요**
1–9주차 전부입니다. `--no-llm` 을 붙이면 문서 작성·검증·컴파일이 됩니다.
`--mock` 을 쓰면 가짜 모델로 실행과 평가까지 돌려볼 수 있습니다.

## 문서 작성

**질문에 답하다가 나가버렸습니다**
저장됐습니다. `edu-agent status` 로 확인하고 `edu-agent review 01` 로 이어가세요.

**문서를 직접 고쳤는데 되돌아갑니다**
`review` 를 다시 실행하면 "본문이 수정되었습니다"라고 묻습니다.
2번(본문 수정을 인정)을 고르면 손으로 쓴 내용이 유지됩니다.

**설계원리를 뭘 써야 할지 모르겠습니다**
`review 02` 에서 라이브러리를 먼저 보게 하세요. 각 항목에 근거 문헌이 붙어 있습니다.
고른 뒤 자기 말로 고치면 됩니다.

## 컴파일

**"P0X 가 아직 확인되지 않았습니다"**
`review 02` 를 다시 실행해 각 원리의 구조화 결과를 확인해야 합니다.
이것은 의도된 관문입니다 — 확인하지 않은 원리는 컴파일되지 않습니다.

**경고가 많이 나옵니다**
경고는 컴파일을 막지 않습니다. 다만 읽을 가치가 있습니다.
특히 W303("모든 단계가 질문입니다")과 W501("정답 기준이 없습니다")은 고치는 것이 좋습니다.

## 평가

**모든 대화에서 학생이 문제를 못 풉니다**
`--mock` 으로 돌리면 정상입니다. 가짜 모델은 실제로 도움이 되는 힌트를 주지 않습니다.
실제 모델로 `edu-agent test` 를 돌려 보세요.

**점수가 너무 높게/낮게 나옵니다**
`--seeds` 를 늘려 보세요(기본 2). 대화 수가 적으면 결과가 불안정합니다.
보고서에도 그런 경우 경고가 표시됩니다.

**"judge 점수는 참고용입니다"가 계속 나옵니다**
`edu-agent calibrate` 를 아직 하지 않았기 때문입니다. 이것은 오류가 아니라 정직한 표시입니다.

**채점했는데도 κ가 0에 가깝습니다**
드문 일이 아닙니다. 먼저 학생이 라벨을 한 값으로만 찍지 않았는지 보세요(전부 `partial` 이면
κ는 0이 됩니다). 그다음 `edu-agent calibrate --tune` 을 돌리게 하세요. 사람 채점의 절반으로
판정 예시를 만들고 나머지 절반으로 검증합니다. **오르지 않으면 되돌리는 것이 정상이며,
그 결과 자체가 13주차 토론거리입니다** — 루브릭 문구의 문제인지, 판정 기준이 이 수업의
의도와 어긋나는지.

## 웹 채팅

**`edu-agent run --web` 이 "포트를 쓸 수 없습니다"**
다른 프로그램이 7860 번을 쓰고 있습니다. `--port 0` 을 붙이면 빈 포트를 자동으로 잡습니다.

**브라우저는 열렸는데 "invalid token" 이 뜹니다**
주소의 `?k=...` 부분이 빠졌습니다. 터미널에 찍힌 주소를 그대로 복사해야 합니다.
(다른 페이지가 학생의 튜터를 조작하지 못하게 하는 장치입니다.)

**창을 닫았는데 대화가 저장되지 않았습니다**
저장은 터미널에서 Ctrl+C 로 서버를 끝낼 때 일어납니다. 창만 닫으면 아직 서버가 살아 있습니다.

## 코드 실행

**`doctor` 가 "격리가 부분적입니다"라고 합니다**
docker 가 없는 컴퓨터입니다. 학생 코드는 시간·메모리 제한과 네트워크 차단만 걸고
그 컴퓨터에서 그대로 돕니다. 학생이 자기 코드만 다루는 수업이라면 이대로 충분합니다.
서로의 코드를 주고받는 활동이라면 Docker Desktop 을 깔게 하거나, `edu-agent.yaml` 에서
`sandbox.backend: disabled` 로 꺼 두세요.

**"C 컴파일러(gcc)를 찾을 수 없습니다"**
Windows 에는 기본으로 없습니다. Codespaces 를 쓰면 바로 됩니다. 로컬이라면 MSYS2/MinGW 나
WSL 을 깔아야 합니다. 컴파일러가 없어도 다른 기능은 전부 동작합니다.

**튜터가 코드를 실행하지 않고 "조건을 만족하지 않았습니다"만 남깁니다**
의도된 동작입니다. 기본 조건은 "학습자가 자기 생각을 먼저 말한 뒤"입니다.
바꾸려면 `03_technical_spec.md` 의 도구 `when_allowed` 를 고치고 다시 컴파일하세요.

## 개선

**`improve` 가 아무것도 안 바꿉니다**
개선 폭이 기준(+0.05)에 못 미치면 되돌립니다. 정상 동작입니다.
`--dry-run` 으로 무엇을 제안했는지 먼저 보게 하세요.

**"직접 판단이 필요합니다"만 나옵니다**
설계원리 자체를 고쳐야 하는 문제입니다. 하네스는 이것을 자동으로 하지 않습니다.
02 문서를 열어 학생이 직접 판단해야 합니다.

**바꾼 것을 되돌리고 싶습니다**
```bash
edu-agent improve --history
edu-agent improve --rollback 2
```
