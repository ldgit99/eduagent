# API 키 배포 전략

학생이 직접 결제하거나 키를 발급받게 하지 마세요. 하네스는 환경변수 **세 개**만 읽습니다.

```
EDU_AGENT_API_KEY=
EDU_AGENT_BASE_URL=
EDU_AGENT_MODEL=
```

이 세 줄을 프로젝트 폴더의 `.env` 에 넣으면 됩니다. `.env` 는 `.gitignore` 에 있어
GitHub에 올라가지 않습니다.

## 선택지 비교

| 방식 | 비용 통제 | 학생 부담 | 키 유출 대응 | 권장 |
|---|---|---|---|---|
| **교수자 운영 OpenAI 호환 프록시** | 학생별 한도 | 붙여넣기만 | 개별 폐기 | ★ |
| 무료 티어 provider | 자동 | 가입 필요 | — | 보조 |
| 공용 키 하나 | 어려움 | 없음 | 전체 교체 | 비권장 |
| Ollama 로컬 | 비용 0 | 고사양 PC 필요 | 불필요 | 일부 학생 |

## 권장: 교수자 프록시

OpenAI 호환 엔드포인트를 제공하는 게이트웨이(LiteLLM Proxy, Vercel AI Gateway,
자체 서버 등)를 하나 띄우고 학생별 키를 발급합니다. 하네스는 `base_url` 만 바꾸면
그대로 동작합니다.

```
EDU_AGENT_BASE_URL=https://ai-proxy.our-school.ac.kr/v1
EDU_AGENT_API_KEY=학생별-발급-키
EDU_AGENT_MODEL=gpt-4o-mini
```

얻는 것:
- 학생별 사용량과 월 한도
- 키가 유출돼도 그 학생 것만 폐기
- 어떤 학생이 막혀 있는지 사용량으로 파악

## 비용 줄이기

수업 규모(30명)에서 비용이 나가는 곳은 **11–14주차의 `test` 반복**입니다.

1. **세션당 토큰 상한**을 두세요. `edu-agent.yaml` 의
   `provider.max_tokens_per_session` (기본 20000).
2. **`--regrade` 를 쓰게 하세요.** 저장된 대화를 튜터 모델 재호출 없이 다시 채점합니다.
   판정 기준만 바꿔 보는 경우 비용이 들지 않습니다.
   ```bash
   edu-agent test --regrade latest
   ```
3. **`--no-llm` 으로 자동 검사만** 먼저 돌리게 하세요. 정답 누출·게이트 준수 같은
   중요한 검사는 모델 없이 됩니다.
4. **`--seeds 1` 로 시작**하고, 결과가 안정적인지 확인한 뒤에 늘리게 하세요.
5. **시뮬레이션 학생은 기본이 템플릿**입니다(모델 호출 없음). `--llm-student` 를
   붙일 때만 모델을 씁니다.

## 학생 모델과 평가 모델

가능하면 셋을 다르게 두세요.

```
EDU_AGENT_MODEL=gpt-4o-mini            # 튜터
EDU_AGENT_JUDGE_MODEL=gpt-4o           # 평가자 (더 강한 모델)
EDU_AGENT_STUDENT_MODEL=gpt-4o-mini    # 시뮬레이션 학생 (더 약해도 됨)
```

같은 모델이 튜터와 평가자를 겸하면 자기 맹점을 그대로 물려받습니다. 학생 역할은
오히려 **약한 모델이 실제 학생과 더 비슷**하다는 결과가 있습니다
(`docs/research/student-simulation.md`).

## 개인정보

- 학생에게 **실제 학생·동료의 대화를 넣지 말라**고 안내하세요. 시뮬레이션 학생은
  합성 데이터입니다.
- `run` 은 시작할 때 "이 대화는 이 컴퓨터에만 기록됩니다"를 표시합니다.
- 제출은 `report` 가 만든 요약본으로 받으세요. `.edu-agent/` 폴더는 커밋되지 않습니다.
