# 언어

이 하네스는 한국어 수업을 위해 만들어졌고, 기본 언어는 한국어입니다.
영어 지원은 "한국어 문자열을 전부 번역한다"가 아니라 **문자열을 세 종류로
나누고, 종류마다 다르게 다룬다**는 뜻입니다.

번역할 것과 번역하면 안 되는 것을 구분하지 않으면, 영어 수업에서 한국어
탐지 규칙이 조용히 사라집니다. 이 문서는 그 경계를 적어 둔 것입니다.

---

## 세 종류

### 1. UI — 사람이 화면에서 읽는 말

질문, 안내문, 오류 메시지, 선택지 라벨. **카탈로그로 옮깁니다.**

- `src/edu_agent/i18n/ko.yaml`, `en.yaml`
- 코드에서는 `t("principles.answer.question")` 처럼 키로만 부릅니다

```python
# 이렇게 하지 않습니다
ui.note("여러 줄로 쓸 수 있습니다.")

# 이렇게 합니다
ui.note(t("ui.multiline"))
```

카탈로그는 두 파일이 같은 키를 가져야 하고(`test_catalogues_cover_the_same_keys`),
모든 키가 자기 이름이 아닌 문장으로 풀려야 합니다
(`test_every_key_resolves_to_text_not_its_own_name`).

**선택지의 값도 UI입니다.** 02 질문지에서 고른 이론 이름과 인계 문장은 그대로
문서와 시스템 프롬프트에 들어갑니다. 영어 프로젝트라면 영어로 저장되어야
하므로, 라벨뿐 아니라 값도 카탈로그에서 가져옵니다.

> **선택지 목록은 함수로 만듭니다.** `set_language()` 는 프로젝트를 열 때
> 호출되고, 그때는 모듈이 이미 import 된 뒤입니다. 모듈 최상위에서
> `Choice("1", t(...))` 를 만들면 import 시점의 언어로 굳어집니다.
> 같은 이유로 언어 해석을 `lru_cache` 안에 두면 안 됩니다 — 기본 인자가
> 캐시 키의 일부라서, 프로세스의 첫 호출이 언어를 고정해 버립니다.

### 2. 생성물 — 이 하네스가 만들어 내는 문서

4개 문서, 보고서, 내보내는 프로젝트의 소스. **템플릿으로 옮깁니다.**

- `templates/ko/`, `templates/en/` — 언어별로 갈라지고, 없으면 한국어로 대체
- `templates/export/`, `templates/web/` — 언어와 무관한 스캐폴드

프롬프트에 들어가는 문장도 여기에 속합니다:

- `src/edu_agent/runtime/actions.yaml` — 행동 설명 (`ko:` / `en:`)
- `src/edu_agent/compiler/safety.yaml` — 안전 규칙

이 문장들의 언어는 **터미널이 아니라 프로젝트**를 따릅니다. 실제로는 같은
값입니다 — `load_project()` 가 프로젝트 설정에서 현재 언어를 정하기 때문입니다.

### 3. 로캘 콘텐츠 — 번역하면 안 되는 것

특정 언어에 묶인 **탐지 규칙과 예시**입니다. 영어 수업에는 이것을 *대신할*
영어 규칙이 아니라 영어 규칙이 *추가로* 필요합니다.

| 파일 | 무엇 | 번역하면 |
|---|---|---|
| `runtime/triggers.py` | 한국어 개인정보 정규식, 좌절·포기 표현 탐지 | 한국어 학습자의 개인정보가 통과합니다 |
| `simulator/renderer.py` | 시뮬레이션 학생의 한국어 발화 | 한국어 에이전트를 영어로 시험하게 됩니다 |

이 두 파일은 언젠가 `triggers/{ko,en}.yaml` 처럼 언어별로 **덧붙이는** 구조가
되어야 합니다. 지금은 한국어만 있고, 그것이 정직한 상태입니다.

**설계원리 라이브러리**(`principles/library/{lang}/`)도 여기에 가깝습니다.
문헌을 인용한 학술 텍스트라서 기계적으로 옮길 수 없습니다. 구조만 준비해
두었고, `en/` 이 없으면 한국어로 대체됩니다. 번역본을 쓸 때는 `library_id` 를
그대로 두어야 합니다 — 프로젝트 문서에 기록된 값이고, 나중에 다른 언어로
열어도 찾을 수 있어야 하기 때문입니다.

## 지금 어디까지 왔나

`tests/test_i18n.py` 의 `MIGRATED_MODULES` 가 사실상의 진행 상황표입니다.
여기 올라온 모듈은 docstring 과 주석 말고는 한국어 문자열을 가질 수 없고,
테스트가 그것을 강제합니다.

```
ui.py                        모든 질문에 붙는 안내문
questionnaire/principles.py  02 설계원리 질문지 (가장 긴 대화)
```

아직 옮기지 않은 것:

- `questionnaire/educational.py`, `technical.py` — 01·03 질문지
- `cli.py` 를 제외한 나머지 명령·보고 계층

### `cli.py` 는 왜 빠져 있나

Typer 는 명령 도움말을 **import 시점에** 함수 시그니처와 docstring 에서
읽습니다. `--lang` 은 그보다 늦게 파싱됩니다. 카탈로그를 바꾼다고 해결되지
않고, 도움말을 지연 평가하는 별도의 장치가 필요합니다. 카탈로그 문제가
아니므로 `MIGRATED_MODULES` 에 넣지 않았습니다.

## 옮기는 방법

1. 대상 모듈의 사용자 대상 문자열을 모읍니다.
2. `ko.yaml` 에 섹션을 만들고, `en.yaml` 에 같은 키를 채웁니다.
3. 코드를 `t("...")` 로 바꿉니다. 선택지 목록은 함수로 만듭니다.
4. `MIGRATED_MODULES` 에 파일을 추가합니다.
5. `pytest tests/test_i18n.py` — 가드 테스트가 남은 한국어를 줄 번호와 함께
   알려 줍니다.

문자열을 옮기다 보면 서식 인자 이름이 템플릿 변수와 충돌할 수 있습니다.
`render_document(name, lang, ...)` 에 `lang` 이라는 변수를 가진 템플릿을 주면
인자가 먹힌 적이 있습니다 — 경로를 positional-only 로 받는 `render_template`
이 그래서 따로 있습니다.
